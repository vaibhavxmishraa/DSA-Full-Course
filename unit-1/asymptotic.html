CONCEPT 01

What is Asymptotic Analysis?

Asymptotic analysis is a technique used to analyse the efficiency of an algorithm as the input size n becomes very large.

We generally ignore machine-dependent details such as processor speed and focus on the growth rate of the algorithm.

For example:

3n² + 5n + 10

For very large n, the n² term dominates. Therefore its asymptotic growth is:

3n² + 5n + 10 = Θ(n²) Lower-order terms and constant coefficients are ignored for growth-rate analysis.

NOTATION 01

Big-O O(f(n))

Upper Bound

Big-O describes an asymptotic upper bound on the growth of an algorithm.

In simple language:

"Algorithm ki growth isse zyada fast asymptotically nahi hogi."

T(n) = O(f(n)) T(n) grows no faster than a constant multiple of f(n), asymptotically.
big-o.cpp 
for(
    int i=0;
    i<n;
    i++
)
{
    cout << i;
}

Analysis

The loop executes n times.

Therefore:

T(n) = O(n)
NOTATION 02

Big-Omega Ω(f(n))

Lower Bound

Big-Omega describes an asymptotic lower bound.

"Algorithm ko at least itna work asymptotically karna padega."

Example: If an algorithm always needs to inspect at least n elements, then its lower bound can be expressed as Ω(n).

T(n) = Ω(f(n)) T(n) grows at least as fast as a constant multiple of f(n), asymptotically.
NOTATION 03

Big-Theta Θ(f(n))

Tight Bound

Big-Theta is used when we know both the upper and lower asymptotic bounds.

"Growth exactly isi order ki hai."

For example:

T(n) = 3n² + 5n + 10

Its dominant term is n². Therefore:

T(n) = Θ(n²)

IMPORTANT

Best vs Average vs Worst

🟢

Best Case

Minimum work performed by the algorithm for a favourable input.

Example: Linear Search → O(1)
🟡

Average Case

Expected performance for typical or randomly distributed input.

🔴

Worst Case

Maximum work performed for the most unfavourable input.

Example: Linear Search → O(n)
