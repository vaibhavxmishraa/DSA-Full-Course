COMPLEXITY

Writing a correct algorithm is not enough. We also need to know how efficiently it performs when the input size becomes huge. Complexity analysis helps us measure time and memory requirements.

CONCEPT 01

Why do we need Complexity?

Simple Idea

Suppose two algorithms both solve the same problem correctly. Algorithm A takes 1 second while Algorithm B takes 5 minutes.

Obviously, we would prefer Algorithm A. But instead of measuring actual seconds, DSA uses mathematical growth rates to compare algorithms independent of machine speed.

This analysis is called Complexity Analysis.

⏱️

Time Complexity

Measures how the number of operations performed by an algorithm grows as input size n increases.

💾

Space Complexity

Measures how much memory an algorithm requires as the input size increases.

CONCEPT 02

Time Complexity

Time complexity does not literally mean the number of seconds taken by a program.

It describes the growth in number of operations as input size n grows.

Example:

If a loop runs n times, its time complexity is approximately O(n).

O(1)

Constant

Runtime remains almost independent of input size.

🚀 Excellent
O(log n)

Logarithmic

Problem size is repeatedly reduced, usually by half.

⚡ Very Fast
O(n)

Linear

Operations grow directly with input size.

👍 Good
O(n log n)

Linearithmic

Commonly seen in efficient sorting algorithms.

⚡ Efficient
O(n²)

Quadratic

Usually caused by nested loops over n.

🐢 Slow
O(2ⁿ)

Exponential

Growth becomes extremely large very quickly.

⚠️ Very Slow

EXAMPLE 01

Constant Time — O(1)

constant.cpp 
int arr[] = {10, 20,
              30, 40};

cout << arr[0];

Why O(1)?

Whether the array contains 10 elements or 10 million elements, accessing arr[0] requires approximately the same operation.

Therefore:

Time Complexity = O(1)
EXAMPLE 02

Linear Time — O(n)

linear.cpp 
for(
    int i=0;
    i<n;
    i++
)
{
    cout << arr[i];
}

Why O(n)?

If n = 10, the loop executes about 10 times.

If n = 1000, it executes about 1000 times.

Operations grow directly with n.

Time Complexity = O(n)
EXAMPLE 03

Quadratic Time — O(n²)

nested-loop.cpp 
for(
    int i=0;
    i<n;
    i++
)
{
    for(
        int j=0;
        j<n;
        j++
    )
    {
        cout << i << j;
    }
}

Why O(n²)?

Outer loop executes n times.

For every outer iteration, inner loop also executes n times.

Therefore: n × n = n²

Time Complexity = O(n²)
CONCEPT 03

Space Complexity

Space complexity tells us how much memory an algorithm needs while solving a problem.

Example:

int x; requires a fixed amount of memory, so it is generally considered O(1) auxiliary space.

But if we create an array of n elements:

int arr[n]; memory grows with n, so it is O(n).

IMPORTANT

Best, Average & Worst Case

🟢

Best Case

Minimum number of operations required for a particular input.

🟡

Average Case

Expected performance over typical or random inputs.

🔴

Worst Case

Maximum number of operations an algorithm may require for an input.

REAL DSA EXAMPLE

Linear Search & Complexity

Suppose we have:

[10, 20, 30, 40, 50]

We want to find 50. Linear Search checks elements one by one.

↓

↓

Best case: O(1) if the first element is the target.

Worst case: O(n) if the target is at the last position or does not exist.

🧠 Golden Rule

Generally, as input size becomes very large, algorithms with slower-growing complexity are preferred.

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
